## 1. 需求

将误写在旧目录 `/data/case/LlamaLens` 的 SGLang 多引擎支持移植回当前目录，并适配当前目录已领先 46 个提交的 DB 主机管理、gateway、terminal 架构。

目标：

- 新增 `backend/engine/` 统一引擎抽象层。
- `llama_cpp` 保持现有监控行为不回归。
- `sglang` 支持只读采集：`/v1/loads`、`/get_server_info`、`/get_model_info`、`/v1/models`。
- 前端按 `snap.engine.type` 展示 `SglangStateCard` 或 llama.cpp 原有形态。
- 主机数据库与主机管理界面支持 `engine_type=sglang` 及 API Key。
- 保留当前目录已有未提交 gateway 改动。

## 2. 关键约束

- 不修改旧目录 `/data/case/LlamaLens`。
- 不覆盖当前目录已有未提交改动。
- 不提交 commit、不创建分支、不推送。
- 不实现 SGLang 写接口。
- 不改变 llama.cpp 主行为。
- SGLang API Key 必须加密存储、脱敏返回、支持 `.env` 引用。

## 3. 移植策略

旧目录 SGLang 代码基于 9/1 旧架构，不能直接覆盖当前文件。采用“复制新增文件 + 手动适配现有文件”：

1. 复制新增文件：
   - `backend/engine/`
   - `frontend/src/components/SglangStateCard.vue`
   - `docs/plans/2026-09-30-多引擎抽象层方案.md`
2. 适配后端：
   - `backend/config.py`：新增 `EngineCfg`、`HostConfig.engine`、`process_cmdline`、`queue` 阈值。
   - `backend/monitor.py`：用 `create_engine()` 替换直接 `LlamaPoller` / `LogPoller`。
   - `backend/events.py`：支持 `engine_name`，保留 `llama_up/down` 事件类型以兼容现有前端/通知。
   - `backend/alerts.py`：基于 engine block 判断，新增 SGLang queue 告警。
   - `backend/api.py`：`/health` 增加 `engine` / `engine_online`。
   - `backend/history.py`：新增 `accept_length` 序列。
   - `backend/pollers/ssh_host.py`：支持 `process_cmdline` 固定串进程识别。
3. 适配 DB 主机管理：
   - `backend/ctl/database.py`：hosts 表增加 engine 字段。
   - `backend/ctl/hostsync.py`：DB row 组装 `HostConfig.engine`，YAML 导入支持 engine 块。
   - `backend/ctl/routers/hosts.py`：主机新增/编辑支持 engine 字段，API Key 加密并脱敏。
4. 适配前端：
   - `HostDetailView.vue`
   - `TopBar.vue`
   - `HostCard.vue`
   - `ModelInfoCard.vue`
   - `LlamaProcessCard.vue`
   - `HostManager.vue`
5. 文档同步：
   - `.env.example`
   - `README.md`
   - `docs/01-需求文档.md`
   - `docs/02-架构设计文档.md`
   - `docs/03-UI与交互设计文档.md`

## 4. 数据模型

### 4.1 EngineCfg

```python
@dataclass
class EngineCfg:
    type: str = "llama_cpp"
    host: str = ""
    port: int = 0
    interval: float = 1.0
    slow_interval: float = 30.0
    timeout: float = 3.0
    api_key: Optional[str] = None
```

规则：

- 缺省 `type=llama_cpp`。
- `llama_cpp` 继续读取 `llama` 配置。
- `sglang` 缺省端口 `30000`。
- `engine.host` 为空时回退到 `llama_host` 或主机 `host`。
- `api_key` 支持 `${ENV}`，运行时解析。

### 4.2 hosts 表新增字段

- `engine_type TEXT NOT NULL DEFAULT 'llama_cpp'`
- `engine_host TEXT NOT NULL DEFAULT ''`
- `engine_port INTEGER NOT NULL DEFAULT 0`
- `engine_interval REAL NOT NULL DEFAULT 1.0`
- `engine_slow_interval REAL NOT NULL DEFAULT 30.0`
- `engine_timeout REAL NOT NULL DEFAULT 3.0`
- `engine_api_key_enc TEXT`
- `process_cmdline TEXT NOT NULL DEFAULT ''`

已有数据库使用非破坏性 `ALTER TABLE` 迁移。

## 5. 快照兼容

`HostMonitor.snapshot()` 新增：

```python
"engine": block
"llama": block if block.type == "llama_cpp" else compat_copy
```

`llama_cpp` block 与旧 `snap.llama` 同形，并额外携带：

- `type: "llama_cpp"`
- `ctx`

非 llama 引擎的 `snap.llama` 兼容副本：

- `log=None`
- `slots=[]`
- `model` / 速度等从 engine block 复制

必须保留当前目录已有行为：

- `log_snap.pop("task_history", None)`
- `host_metrics` 排除 `_model_sizes`
- `host_metrics` 排除 `all_services`
- `_ws_hub` 关闭逻辑
- notify 逻辑

## 6. 事件与告警

### 事件

为兼容现有前端事件流、通知和历史事件，保留：

- `llama_up`
- `llama_down`

仅把事件文案改为动态：

- `llama 上线`
- `SGLang 上线`
- `SGLang 离线`

`set_llama_online()` 增加 `engine_name="llama"` 参数。

### 告警

`evaluate_alerts()` 改为接收 engine block：

- `engine.online`
- `engine.ctx.pct`
- `engine.log.mtp.acceptance`
- SGLang `engine.requests.waiting`

新增默认阈值：

```python
"queue": {"warn": 8, "danger": 16}
```

llama.cpp 离线继续使用 `metric="llama"`，SGLang 离线使用 `metric="engine"`，避免污染 llama 专属统计。
