## 1. 背景与目标

### 1.1 背景

- 局域网内存在 llama.cpp llama-server 推理实例（首台：ai.lan），运行 Qwen3.8-27B-Q6_K（27.32B 参数，双 RTX 3080 tensor split 推理，带视觉能力）。
- 目前没有任何可视化手段观察实例负载：token 生成速度、GPU 利用率/显存/温度/功耗、CPU、内存、进程状态等只能靠 SSH + nvidia-smi + 手工命令查看。
- 后续会接入更多推理主机，需要"每台主机一个页面 + 统一门户"的监控方案。

### 1.2 目标

1. 构建 Web 监控面板 llama灵境，部署在本机（单进程，端口 8000），远程监控 N 台推理主机（llama.cpp llama-server / SGLang，引擎抽象层可平滑扩展 vLLM）。
2. 每台主机有独立详情仪表盘，门户页聚合所有主机。
3. 数据 1 秒粒度实时刷新（可配置），高科技、动态的视觉风格。
4. 详细展示所有 AI/llama 相关信息（80+ 数据项，完整清单见 §7）。
5. 纯展示、不做告警通知，但指标超阈值必须视觉飘红。

### 1.3 非目标（本期）

- 不做告警推送（邮件/IM/webhook）
- 不做历史数据持久化（仅内存环形缓冲，重启丢失）
- 不做用户认证（局域网内部工具）
- 不修改被监控主机任何配置（不加 --metrics 参数、不装 agent）
- 不做 Docker/K8s 打包（run.sh 直接运行；Docker 为后续迭代）

## 2. 术语

| 术语 | 说明 |
|---|---|
| llama-server | llama.cpp 官方 HTTP 推理服务（本实例为定制构建 llama-cpp-turboquant） |
| Slot | llama-server 并发会话槽位（-np 1 表示 1 个 slot） |
| tok/s | 每秒生成 token 数 |
| Prompt 处理速度 | prompt token 预填充速度（tok/s） |
| Tensor split | 模型层切分到多 GPU（-ts 24,20） |
| 投机解码 | draft-mtp 投机解码（--spec-type draft-mtp --spec-draft-n-max 3） |
| 主机 | 一台被监控的推理机（在主机管理中注册，engine.type 声明推理引擎） |
| 引擎抽象层 | EngineAdapter 统一采集接口（backend/engine/），屏蔽 llama.cpp / SGLang 差异；一期支持 llama_cpp / sglang |
| 门户页 | 列出所有主机的一级页面（/） |
| 详情页 | 单主机仪表盘（/host/:id） |
| 阈值飘红 | 指标超过阈值时的视觉高亮（黄=警告 / 红=危险） |

## 3. 用户与使用场景

- **用户**：AI 基础设施运维 / 开发者（局域网内）
- **使用场景**：
  1. 日常巡检：打开门户页，一眼看到所有主机状态
  2. 任务监控：长推理任务运行时，实时观察 token 速度与 GPU 负载
  3. 故障排查：任务变慢时，查看 GPU 利用率/温度/功耗/PCIe 链路是否异常
  4. 容量评估：观察内存/磁盘/上下文占用，判断实例是否接近上限

## 4. 功能需求

### FR-01 多主机管理与配置

- 主机在 `config/hosts.yaml` 注册：id、名称、llama 地址（host:port）、SSH（host/port/user/password）、采集间隔、阈值覆盖
- 增删主机只需改配置 + 重启服务，不改代码
- 每台主机独立监控：一台故障不影响其他主机与面板自身
- 首台主机为 ai.lan（实测环境见附录 A）

### FR-02 主机门户页（/）

- 顶部品牌栏：llama灵境 标识、主机总数 / 在线数
- 主机卡片墙（网格布局），每卡展示：
  - 主机名 + 状态点（在线绿脉冲 / 离线红 / SSH 断开黄）
  - 模型名 + 参数量
  - Token 生成速度（大数字 + 60s sparkline）
  - 每 GPU 一条利用率条（每卡一行）
  - CPU 利用率、内存使用
  - 超阈值飘红（红边框 + 红色角标）
- 点击卡片进入详情页 /host/:id
- 门户页同样实时刷新（1s）

### FR-03 单主机详情仪表盘（/host/:id）

- 完整布局见 03-UI与交互设计文档.md §3；分区为：
  TopBar / 实时总览区（4 卡：3 条卡 + 1 仪表）/ GPU 区（按卡聚合）/ 实时生成任务区（状态卡 + 事件流）/ 系统区 / 进程区 / 模型与 Slot 区 / 趋势区（12 图 3 组）

### FR-04 AI 核心指标

- 展示位置：速度 / 上下文占用为条卡（上下文占用大数字为原始 token 数，百分比在右上角）、MTP 接受率为仪表（值驱动颜色），均位于实时总览区（见 03-UI与交互设计文档 §3.3）；任务状态与事件流位于实时生成任务区（§3.4）
- Token 生成速度（tok/s）：实时值 + sparkline + 历史曲线
  - 主数据源：日志 tg_3s（3 秒窗口实时速度，服务端计算，更准）；兜底：/slots n_decoded 差分
- Prompt 处理速度（tok/s）：同上
  - 主数据源：日志 prompt processing 行（实时速度 + 进度 %）；兜底：/slots n_prompt_tokens_processed 差分
- 上下文占用：已用/总量及百分比
  - 主数据源：日志 release 行 n_tokens（权威值，含系统提示词）；兜底：/slots（n_prompt_tokens + n_decoded）
  - 展示：已用（原始 token 数大数字）、百分比（右上角）、剩余、总量（n_ctx，条满量程与刻度）、是否被截断（truncated）
- 任务状态：运行中/空闲、任务 ID、剩余 token（n_remain）、当前任务累计已解码（n_decoded）
- 任务级统计：任务结束时记录总 token 数、耗时、平均速度、MTP 接受率、上下文占用（进入事件流）

### FR-05 GPU 监控（按卡聚合）

- 每张 GPU 一个独立面板，包含该卡全部指标：
  - 利用率（环形仪表）
  - 显存：used/free/total + 进度条
  - 温度、功耗（draw/limit）、风扇转速、图形频率、显存频率
  - PCIe 链路（gen/width）、性能状态（P-state）
  - 驱动版本、卡型号
  - 占用该卡的进程（pid/name/显存）
- 历史曲线：利用率、显存（每卡一条线）

### FR-06 系统资源监控

- CPU：型号、核数、整机利用率、每核利用率（每核一根条）、load 1/5/15、主频
- 内存：total/used/free/buff_cache/available、swap used/total
- 磁盘：每挂载点 size/used/avail/百分比 + 读写速率
- 网络：每网卡 rx/tx 速率与累计
- 系统：主机名、内核、OS 版本、uptime、进程总数

### FR-07 进程监控

- llama-server 进程卡：
  - PID、实时 CPU%（差分）、累计 CPU%、RSS、VSZ、线程数、运行时长
  - systemd 服务状态（unit 名/描述/active/启动时间/服务级 CPU 累计/服务级内存含峰值/Tasks 数）
  - 完整命令行（可折叠）+ 解析参数表（model、mmproj、n-gpu-layers、flash-attn、tensor-split、batch、ubatch、np、ctx-size、kv-offload、cache-type-k/v、fit、threads、threads-batch、threads-http、temperature、top-p、top-k、spec-type、spec-draft-n-max、port、host）
- Top 进程：按 CPU Top 8、按内存 Top 8（pid/name/cpu%/mem%/rss）

### FR-08 模型与 Slot 详情

- 模型信息：名称、路径、ftype、参数量、嵌入维度、词表大小、文件体积、mmproj 体积、模态（vision/video/audio）、n_ctx、n_ctx_train、vocab_type、capabilities、owned_by
- Slot 详情：id、状态、任务 ID、prompt tokens（总/已处理/缓存）、已解码、剩余、上下文占用%、全量采样参数（temperature、dynatemp_*、top_k、top_p、min_p、top_n_sigma、xtc_*、typical_p、repeat_last_n、repeat_penalty、presence_penalty、frequency_penalty、dry_*、mirostat_*、adaptive_*、max_tokens、n_predict、n_keep、n_discard、ignore_eos、stream、n_probs、min_keep、chat_format、reasoning_format、reasoning_in_content、generation_prompt、samplers、speculative.types、timings_per_token、post_sampling_probs、backend_sampling、lora）

### FR-09 历史趋势图

- 图表类型（12 图 3 组，相关指标相邻）：
  - llama 组：Token 生成速度、预填充速度、**上下文占用（1s 采样线 + n_ctx 上限参考线）**、**MTP 接受率（每任务阶梯趋势）**
  - GPU 组：利用率（每卡）、显存（每卡）、温度（每卡）、功耗（每卡）
  - 系统组：CPU、内存（used/buff_cache 堆叠）、网络（rx/tx）、负载均值（1/5/15 三线）
- 时间窗口切换：5m / 15m / 1h
- 数据源：内存环形缓冲（llama 3600 点 @1s，host 1800 点 @2s）
- 断线时曲线断点（不插值），保留最后值

### FR-10 事件流

- 事件类型：任务开始、预填充开始（prompt 总 token 数）、任务结束（含总 token/耗时/平均速度）、模型变更、llama 上线/下线、SSH 断开/重连、阈值穿越（告警级别升级/恢复）
- 终端风格展示、自动滚动、内存保留最近 200 条
- 每条事件：时间戳 + 级别（info/warn/error）+ 描述

### FR-11 实时刷新机制

- 默认 1 秒刷新（WebSocket 推送为主通道）
- 前端刷新控制：实时（WS）/ 1s / 2s / 5s / 暂停
- 后端推送间隔按主机可配置（push_interval，默认 1s）
- 采集间隔可配置：llama 1s、SSH 2s（默认值）
- WS 断线自动降级为 HTTP 轮询并提示

### FR-12 阈值飘红

- 两级色阶：黄（warn）/ 红（danger），规则表见 §8
- 飘红效果：数字变红 + 卡片边框红光 + 脉冲动画
- 阈值可按主机覆盖
- 纯视觉，不做通知推送

### FR-13 llama-server 日志解析

- 实时 tail systemd journal（journalctl -u llama-server），解析以下日志行：
  - `print_timing ... n_decoded = X, tg = Y t/s, tg_3s = Z t/s`（生成中每 3s）：实时速度、任务平均速度、已解码数
  - `print_timing ... prompt processing, n_tokens = X, progress = P, t = T s / S t/s`（预填充中每 ~2s）：prompt 进度、prompt 速度
  - `print_timing ... prompt eval time / eval time / total time / graphs reused / draft acceptance`（任务结束汇总）：prompt/解码/总耗时、CUDA graph 复用数、**MTP 接受率/接受数/平均接受长度**
  - `release ... stop processing: n_tokens = X, truncated = T`（任务结束）：**上下文总占用、是否被截断**
  - `get_availabl ... selected slot by LCP/LRU, f_sim_best = X, f_keep = Y`（新任务）：slot 选择方式、LCP 相似度、**KV 缓存保留率**
  - `launch_slot_ ... task N, is_child = C`（任务开始）：任务 ID、是否子任务
  - 启动日志（每次启动一次）：模型路径、n_slots/n_ctx_slot/kv_unified、MTP draft context、KV 缓存类型升级（如 turbo3→q8_0）、verbosity、监听地址、警告列表（CORS、端口变更通知等）
- "llama 当前在干嘛"状态机：prompt 处理（带进度）/ 生成中（带已解码数与速度）/ 空闲
- 日志不可用（SSH 断开 / unit 名不符）→ 回退 /slots 差分，标记 log_available=false
- MTP 参数：静态配置（spec-type/spec-draft-n-max，来自命令行解析）+ 运行时统计（接受率/mean len，来自日志）同时展示


### FR-15 多推理引擎支持（一期：llama.cpp / SGLang）

- 引擎由主机管理界面声明（engine.type：llama_cpp / sglang），不再依赖 hosts.yaml 固定为 llama-server
- 统一引擎抽象层（backend/engine/，EngineAdapter）：采集接口一致（在线状态 / 速度 / 上下文 / 快照块），新引擎（如 vLLM）仅需新增 adapter + 注册
- SGLang 展示项（只读，来源 /v1/loads + /get_server_info + /get_model_info）：
  - 请求队列（running / waiting，多 rank 求和）、生成/预填充速度（prefill 为累计计数器差分）、KV 缓存占用、缓存命中率、GPU 利用率
  - 投机解码：accept_length（替换 llama 的 MTP 接受率仪表）
  - 显存分区（权重 / KV / 激活）、服务配置（模型路径、量化、KV dtype、最大上下文、model_type）
- llama 专属项（Slot、MTP 接受率、日志解析）在 SGLang 主机不硬造数据：对应卡位显示占位/隐藏
- 事件复用现有类型：上线/下线事件仍为 llama_up / llama_down（engine_name 参数区分引擎）；离线告警的 metric 名按引擎区分（llama 主机报 llama，SGLang 主机报 engine）
- 新增阈值：SGLang 排队请求数 queue（waiting）warn=8 / danger=16，仅 SGLang 主机评估
- 纯只读：不调用任何 SGLang 写接口
- 进程识别：SGLang 主机按固定串匹配 cmdline（默认 "sglang serve"，可配置，白名单字符校验，≤128 字符）

### FR-14 本地 CLI（llamalens）

- 在被监控主机**本地**运行的 htop 风格全屏 TUI，展示内容与单主机详情页（FR-03~FR-13）同源
- 零运行时依赖：单个静态二进制（Go，`CGO_ENABLED=0`），目标主机无需 Go / Python / pip
- 数据本地直采（不经后端、不写文件、不改 llama-server 状态）：
  - llama HTTP API（`/slots`@1s、`/props`+`/v1/models`@30s）
  - `/proc` 直读@2s（CPU/内存/磁盘/网络/负载/Top 进程）
  - `nvidia-smi`@2s（GPU）
  - `systemctl show` + `journalctl -u <unit> -f`（服务状态 + 日志事件流，解析规则同 FR-13）
- 交互：`q` 退出 / `p` 暂停 / `t` 趋势 / `g` GPU；终端 resize 自适应；退出自动恢复终端（无残留）
- 阈值飘红与 Web 面板同源（§8）
- 终端要求：≥80×20，需交互式 TTY；另提供 `--once` 单次文本快照（无 TTY 可用）
- 进程名 / unit / 端口须与 hosts.yaml 对应主机一致
