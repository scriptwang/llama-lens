# LlamaLens 合并方案（监控 + 管理一体化）

> 目标：以 **LlamaLens** 为项目主体，吸收 LlamaCtl-Web 的管理能力，
> 形成一个"先监控、后管理"的综合性 llama.cpp 多主机平台。
> 主机管理参考 LlamaCtl-Web（UI 管理 + 凭证加密入库），监控沿用 LlamaLens 现有实现。

## 1. 定位与原则

- **监控优先**：门户页/主机详情页保持 LlamaLens 现有体验不变，是产品第一入口。
- **管理为第二层**：服务启停、systemd 单元编辑、日志查看等能力挂在主机详情之下，不改变主导航结构。
- **单一主机源**：合并后主机只有一份数据（SQLite），监控与管理共用，废弃 `hosts.yaml` + `.env` 作为运行时配置（保留为一次性导入源）。
- **最小侵入**：LlamaLens 现有监控链路（pollers / monitor / ws / store）不动，管理模块以独立包形式并入。

## 2. 总体架构

```
LlamaLens（单进程 :8000，FastAPI 托管 frontend/dist）
├── backend/
│   ├── main.py            # 入口（lifespan：init_db → 加载主机 → 启动 MonitorRegistry）
│   ├── config.py          # 全局配置（阈值/推送间隔/服务端口），不再承载主机列表
│   ├── store.py           # 监控数据（RingBuffer 等，不变）
│   ├── monitor.py         # HostMonitor / MonitorRegistry（改造：支持运行时增删主机）
│   ├── api.py             # 监控只读 API（不变）
│   ├── ws.py              # WS 推送（不变，加鉴权）
│   ├── pollers/           # 采集层（不变）
│   └── ctl/               # ★ 新包：从 LlamaCtl-Web 移植的管理层
│       ├── database.py    #   SQLite（hosts/users/session_logs/settings）
│       ├── security.py    #   Fernet 凭证加密 + JWT
│       ├── ssh_pool.py    #   管理用 SSH 连接池（按需、短生命周期）
│       ├── core/          #   systemctl / scanner / unitfile / execstart / param_dict
│       └── routers/       #   hosts / services / metrics / logs / rules / params / auth
├── frontend/
│   └── src/
│       ├── views/         # PortalView / HostDetailView（不变）+ LoginView（新增）
│       └── components/    # 现有监控组件 + ★ 移植管理组件
│                          #   HostManager / ServiceCard / ConfigDialog / SourceEditor
│                          #   VisualPanel / HelpViewer / FileBrowser / LogsDrawer
│                          #   MetricsPanel / RuleEditor / NewServiceDialog
├── data/                  # ★ 新增：SQLite + fernet.key + jwt.secret（Docker 挂载卷）
└── config/
    └── config.yaml        # 全局配置（阈值/端口/推送间隔），主机信息移入 DB
```

**两套 SSH 并存（有意为之）**：
- `pollers/ssh_conn.py`：监控用，长连接 + keepalive，高频只读批量采集；
- `ctl/ssh_pool.py`：管理用，按需连接池，执行 systemctl/写单元文件等交互命令。
两者从同一个 hosts 表取凭证，生命周期不同，不强行合并。

## 3. 关键设计决策

### 3.1 主机数据模型（合并 schema）

以 LlamaCtl-Web 的 `hosts` 表为基座，扩展 LlamaLens 监控字段：

| 字段 | 来源 | 说明 |
|---|---|---|
| id / alias / host / port / username / auth_type / encrypted_pwd / key_passphrase_enc | LlamaCtl-Web | SSH 凭证，Fernet 加密 |
| last_connected_at / created_at / browse_paths | LlamaCtl-Web | 管理元数据 |
| llama_host / llama_port / llama_interval / llama_slow_interval / llama_timeout | LlamaLens | llama-server HTTP 端点 |
| ssh_interval / ssh_keepalive / ssh_timeout | LlamaLens | 监控采集节奏 |
| process_name / systemd_unit | LlamaLens | 进程识别与单元名 |
| log_source / log_unit / log_path / log_follow / log_catchup_sec | LlamaLens | 日志采集方式 |
| disk_mounts（JSON） | LlamaLens | df 采集挂载点 |
| thresholds（JSON） | LlamaLens | 每主机阈值覆盖 |
| monitor_enabled（bool） | 新增 | 是否纳入监控（可只管理不监控） |

### 3.2 动态监控注册（核心改造点）

现状：`MonitorRegistry` 在启动时从 `hosts.yaml` 一次性构建，改主机必须重启。
改造：
- 启动时从 SQLite 加载全部 `monitor_enabled` 主机，构建 HostMonitor；
- 主机 CRUD API 成功后热增删：新增 → `registry.add(cfg)` 启动采集任务；删除/禁用 → `registry.remove(id)` 优雅停止（复用现有 `HostMonitor.stop()`）；
- 修改监控字段（llama 端口、阈值等）→ 对该主机执行 remove + add（简单可靠，采集中断 <1s）；
- 修改 SSH 凭证 → 同时刷新监控侧 `SshConnection` 与管理侧 `ssh_pool` 的缓存连接。

### 3.3 API 布局（解决路由冲突）

LlamaLens 现有 `GET /api/hosts`（监控列表）与 LlamaCtl-Web `/api/hosts`（CRUD）冲突，统一为：

| 路由 | 说明 |
|---|---|
| `GET /api/hosts` | 统一主机列表：DB 字段 + 监控实时状态（在线/离线/告警数） |
| `POST /api/hosts` / `PUT /api/hosts/{id}` / `DELETE /api/hosts/{id}` | 主机 CRUD（含连接测试 `POST /api/hosts/{id}/test`） |
| `GET /api/hosts/{id}/overview` / `history` / `events` | 监控只读（不变） |
| `GET /ws/hosts/{id}` / `GET /ws/portal` | WS 推送（不变，加 JWT 校验） |
| `/api/services/**` `/api/metrics/**` `/api/logs/**` `/api/rules/**` `/api/params/**` | 管理 API（从 LlamaCtl-Web 平移，前缀不变） |
| `/api/auth/login` `/api/auth/me` | 登录（`auth_enabled=false` 时跳过） |

前端 `api.js` 相应合并；Go CLI 依赖的 `GET /api/hosts` 响应保持向后兼容（新增字段不破坏旧客户端）。

### 3.4 鉴权

- 采用 LlamaCtl-Web 方案：JWT + 本地账号（首次启动生成 admin/随机密码，可配置关闭）；
- 所有 `/api/**` 与 `/ws/**` 统一挂 `get_current_user` 依赖（WS 走 query param token）；
- 管理写操作继续记 `session_logs` 审计表。

### 3.5 前端结构

- 新增 `LoginView`（auth 开启时路由守卫拦截）；
- 门户页 `PortalView`：主机卡片增加"管理"入口；顶栏增加"主机管理"按钮（打开移植的 `HostManager` 对话框：添加/测试/编辑/删除/凭证加密）；
- 主机详情页 `HostDetailView`：现有监控 Tab 不变，新增 **管理** Tab：
  - 服务卡片（扫描结果、启停重启）+ 指标卡片（CPU/内存/GPU/功耗/温度）；
  - 服务日志抽屉（journalctl）；
  - 单元编辑器（源码 + 可视化双模）+ `--help` 查看器 + 文件浏览器；
  - 新建/复制服务对话框、扫描规则编辑；
- 主题：管理组件适配 LlamaLens 的 9 套主题 CSS 变量（LlamaCtl-Web 自带主题系统不整体搬入，仅保留编辑器语法高亮主题）。

### 3.6 部署

- 保持 LlamaLens 单进程 `:8000` + `run.sh` / Docker 双模式；
- 新增 `data/` 目录（SQLite、fernet.key、jwt.secret），Docker 以卷挂载持久化；
- `requirements.txt` 增加 `cryptography`、`PyJWT`；
- 环境变量沿用 LlamaLens 风格（`PORT` 等），管理侧敏感项（`JWT_SECRET`/`FERNET_KEY`）默认自动生成到 `data/`。

## 4. 迁移方案

1. **LlamaLens 老用户**：首次启动检测到 `config/hosts.yaml` 存在且 DB 为空 → 自动导入（主机 + 凭证从 `.env` 解析 + 阈值/采集配置），导入后生成 `config/hosts.yaml.imported.bak`，日志提示"主机管理已迁移到界面"；
2. **LlamaCtl-Web 老用户**：提供一次性导入脚本 `scripts/import_llama_ctl.py`，读取其 `data/llama_ctl.db`（hosts 表，Fernet key 需一并拷贝或重新加密）合并入新库；
3. 导入幂等：按 (host, port, username) 唯一键去重。

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 代码归并 | LlamaCtl-Web 后端平移为 `backend/ctl/`（改 import 路径），前端组件平移；先给 LlamaCtl-Web 补一次 git 提交留底 | 两包并存可启动，监控功能回归通过 |
| P1 主机统一 | 合并 schema、hosts CRUD API、动态 MonitorRegistry、hosts.yaml 自动导入 | UI 增删改主机无需重启，监控实时生效 |

| P3 历史持久化 | SQLite 两级存储（原始 7d + 1m 聚合 90d）、事件落库、长窗口 history API，详见 [05-监控数据持久化方案.md](05-监控数据持久化方案.md) | 重启不丢数据，7d/90d 窗口可查，容量 <400MB/主机 |
| P4 管理前端 | LoginView、HostManager、主机详情"管理" Tab、主题适配、历史时间范围选择器 | 浏览器完成 添加主机→扫描→启停→改参→看日志 全流程 |
| P5 收尾 | 部署（Docker 卷、run.sh）、CLI 兼容、文档（README/需求/架构更新）、v2.0.0 发布 | 原生 + Docker 双模式部署验证 |

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 动态增删主机的生命周期竞态（stop 未完成又 add） | registry 内按 host_id 加锁；add 前等待旧 monitor 完全停止 |
| 两套 SSH 凭证不同步 | 凭证修改走统一入口，同时失效两侧连接缓存 |
| 管理组件与 LlamaLens 主题冲突 | 管理组件样式全部走 CSS 变量，不引入全局样式覆盖 |
| WS 鉴权改造影响现有客户端 | token 缺失且 auth 关闭时放行，保持兼容 |
| LlamaCtl-Web 无 git 历史 | P0 先在其仓库提交一次，再平移，便于回溯 |
| Python 3.9 兼容 | 已检查 LlamaCtl-Web 代码无 3.10+ 语法，平移后跑一遍 lint |
