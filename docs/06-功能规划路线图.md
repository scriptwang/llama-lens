# 06 - 功能规划路线图

> 本文档是 LlamaLens 功能开发的总规划。**所有新功能先在此登记，再动手实现，进度在本文档更新。**
> 状态图例：⬜ 未开始 · 🚧 进行中 · ✅ 已完成
> 优先级：P0 = 高价值/低成本优先 · P1 = 紧随其后 · P2 = 锦上添花

## 现状（已有能力）

| 模块 | 能力 |
|---|---|
| 监控 | CPU/内存/GPU（利用率/显存/功耗/温度）/负载/磁盘/网络/Top 进程；llama 生成速度、slots、上下文、MTP；日志流 + 事件流；趋势图（1m~90d） |
| 服务 | systemd 服务扫描/新建/编辑/启停/重启/日志/复制/恢复；服务进程指标 |
| 主机管理 | 增删改/测试连接/SSH 密码与密钥认证（Fernet 加密）/浏览路径 |
| 文件选择 | SFTP 文件浏览器（新建服务、可视化配置），快捷目录取自主机浏览路径 |
| 配置 | config.yaml（server/global 段）+ 界面（主机/规则/阈值）；历史数据 SQLite 两级持久化 |
| 告警（现状） | 阈值引擎 + 事件检测，**仅页面飘红/事件流，无主动推送** |

## 规划项

### P0-1 告警推送（webhook）✅

**目标**：无人值守——GPU 过热、显存爆、服务挂了、SSH 断开时推送到手机/群，而不是等人看页面。

**范围**：
- [x] 每主机通知配置：开关 / 渠道类型 / webhook URL，在【主机管理】编辑对话框维护，存 hosts 表
- [x] 渠道格式：企业微信 / 钉钉 / 飞书 / Bark（iOS 推送）/ 通用 JSON
- [x] 触发事件：阈值告警（新发/升级/恢复）、llama 上下线、SSH 断连
- [x] 防刷屏：复用事件冷却（ALERT_COOLDOWN_S），只在状态变化时推送；恢复也推送
- [x] 发送失败只记日志，绝不影响监控主流程（异步 fire-and-forget）
- [x] 测试按钮：配置后可一键发送测试消息验证 URL

**实现要点**：
- 新增 `backend/notify.py`：渠道格式化 + httpx 发送（走 SSH_EXECUTOR 线程池或独立小线程池）
- `backend/events.py` EventDetector 增加 notify 回调（与现有持久化 sink 同模式）
- `backend/ctl/database.py` 迁移：hosts 表加 `notify_enabled/notify_type/notify_url` 列
- `HostUpdateReq` / 主机管理 UI 增加三个字段

**验收**：ai 主机配 Bark/企业微信 URL → 手动触发阈值（临时调低阈值）→ 手机收到告警与恢复两条消息；断网时日志有失败记录且监控正常。

**进度日志**：
- 2026-09-07：立项，开始实现
- 2026-09-07：实现完成（5 渠道 + 事件钩子 + 主机管理 UI + 测试接口），端到端验证通过（本地接收器捕获企业微信 markdown 消息）

### P0-2 模型管理 ✅

**目标**：模型从"只能看"到"能管"——清单、适配预估、一键切换。

**范围**：
- [x] 模型清单：扫描主机浏览路径下 `.gguf`（大小/量化格式/是否被服务占用/配对 mmproj）
- [x] 显存适配预估：模型大小 vs 空闲 VRAM/RAM，给出"装得下/紧张/装不下"
- [x] 一键切换模型：改目标服务 `ExecStart` 的 `-m`（含 mmproj）+ daemon-reload + 重启，切换前确认
- [ ] （可选）HuggingFace 下载：填 repo id + 文件名，远端 wget/hf 下载带进度（未做，后续按需）

**实现要点**：
- 复用 SFTP 列目录（`/api/hosts/{id}/fs`）+ 服务配置读写（`/api/services/{name}/config`）
- 新增 `GET /api/hosts/{id}/models`（聚合扫描）+ `POST /api/services/{name}/switch-model`
- 前端：主机详情新增「模型」Tab

**验收**：清单正确显示 /share/AI/LLM 下模型与占用关系；切换模型后服务重启且 llama 上线、模型名更新。

**进度日志**：
- 2026-09-07：实现完成（模型清单 + 混合显存预估 + 一键切换 + 主机详情「模型」Tab），端到端验证通过（切换/还原往返测试，配置字节级一致）
### P1-1 推理测试 / Playground ✅

**目标**：改完配置立刻验证"能不能用"，并测出真实性能。

**范围**：
- [x] 内置聊天框：面板代理 llama-server `/v1/chat/completions`（流式）
- [x] 性能指标：TTFT（首 token 延迟）、tokens/s、总耗时
- [x] Endpoint 信息卡：OpenAI 兼容地址 + 模型名，方便外部客户端接入
- [ ] （可选）简单压测：N 并发短请求，输出吞吐（未做，后续按需）

**实现要点**：后端 SSE 代理（httpx stream）；前端聊天组件 + 指标条。

**验收**：聊天出流式回复；TTFT/t/s 数字与 llama-server 日志量级一致。

**进度日志**：
- 2026-09-07：实现完成（SSE 代理 + TTFT/tokens/s/总耗时 + Endpoint 信息卡 + 主机详情「Playground」Tab），端到端验证通过（真实 27B 模型流式回复，MTP 下 239 tps）
### P1-2 效率统计 ✅

**目标**：回答"这台机器值不值"——产出与能耗。

**范围**：
- [x] 每日/每周 token 产出（历史库生成速度积分）
- [x] GPU 累计耗电（功耗曲线积分 → kWh，可配电价出费用）
- [x] tokens/瓦 效率指标
- [x] 门户/主机详情展示（卡片 + 趋势）

**实现要点**：基于 history.db 聚合查询（复用 stride 采样）；新增 `/api/efficiency?host_id=&range=`。

**进度日志**：
- 2026-09-07：实现完成（/api/efficiency 24h/7d/30d + 电价配置 + 主机详情「效率统计」区 + 门户卡片 tokens/天），真实数据验证通过（24h 35.7 万 tokens / 1.59 kWh / 224.8 tokens/Wh）
### P2-1 一键体检 ✅

**目标**：出问题一键导出诊断报告。

**范围**：
- [x] 聚合：系统状态/GPU/服务状态/API 连通性/最近 50 条事件/最近错误日志
- [x] 输出：页面查看 + 复制/下载 markdown
- [ ] （可选）定时体检 + 结果入事件流（未做，后续按需）
