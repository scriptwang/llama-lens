## 1. 总体架构

### 1.1 架构图

```
                    config/config.yaml (全局配置, gitignore)
                    data/llama_ctl.db (主机, 界面管理)
                              │
┌─────────────────────────────▼──────────────────────────────┐
│  FastAPI 单进程 :8000 (本机部署)                             │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ MonitorRegistry                                       │  │
│  │  ├─ HostMonitor[ai]     ├─ HostMonitor[host2] ...    │  │
│  │  │   ├─ LlamaPoller 1s  │   (每主机独立:              │  │
│  │  │   ├─ SshPoller   2s  │    采集+缓冲+事件)          │  │
│  │  │   ├─ LogPoller (journal 流)                       │  │
│  │  │   ├─ RingBuffer (3600@1s + 1800@2s)               │  │
│  │  │   └─ EventDetector (任务开始/结束/上下线)           │  │
│  └──────────────────────────────────────────────────────┘  │
│  REST: /api/hosts · /api/hosts/{id}/overview|history|events │
│  WS:   /ws/hosts/{id} (1s tick 推送, 可配置)                 │
│  静态:  frontend/dist (Vue3 构建产物)                        │
└─────────────────────────────▲──────────────────────────────┘
                              │ WS 1s / HTTP 降级
              ┌───────────────┴───────────────┐
              │  浏览器 (Vue3 + ECharts)       │
              │  /        主机门户 (卡片墙)     │
              │  /host/:id  单主机详情仪表盘    │
              └───────────────────────────────┘

数据源(每台主机):  推理引擎 HTTP API (llama 8080 / sglang 30000) + SSH 只读批量命令 (22)
```

### 1.2 分层职责

| 层 | 组件 | 职责 |
|---|---|---|
| 配置层 | config.yaml + .env + data/llama_ctl.db | 全局配置 + 主机注册（界面管理，Fernet 加密凭证） |
| 采集层 | EngineAdapter（llama_cpp: LlamaPoller+LogPoller / sglang: HTTP）+ SshPoller | 每主机周期采集 + 日志流，全部只读 |
| 计算层 | SpeedCalculator / DiffEngine | 速度、CPU、磁盘、网络差分计算 |
| 存储层 | RingBuffer | 内存环形缓冲（llama 3600@1s，host 1800@2s） |
| 事件层 | EventDetector | 状态迁移检测 → 事件流 |
| 服务层 | FastAPI | REST + WS + 静态托管 |
| 展示层 | Vue3 SPA | 门户页 + 详情页 |

### 1.3 数据流

```
llama-server :8080 ──HTTP(1s)──▶ LlamaPoller ─┐
sglang :30000 ──HTTP(1s)──▶ SglangEngine ─────┤
                                              ├─▶ SpeedCalculator ─▶ RingBuffer ─▶ REST/WS ─▶ 浏览器
host :22 ──SSH(2s 批量)──▶ SshPoller ─┘         │
                                                └─▶ EventDetector ─▶ EventRing ─▶ /events, WS
```

> 引擎差异由 EngineAdapter 屏蔽，HostMonitor 只面对统一接口；快照经 engine.type 区分，llama 字段保留旧结构兼容。

## 3. 多主机设计

### 3.1 核心抽象

```python
class HostMonitor:
    """每台主机一个独立监控单元"""
    def __init__(self, cfg: HostConfig): ...
    def start(self): ...      # 启动 LlamaPoller + SshPoller + 推送任务
    def stop(self): ...
    def snapshot(self) -> dict: ...   # 当前快照（含 alerts）
    def history(self, window_s: int) -> dict: ...
    def events(self, limit: int) -> list: ...

class MonitorRegistry:
    """管理所有 HostMonitor"""
    def load(self, path: str): ...    # 解析 config.yaml
    def get(self, host_id: str) -> HostMonitor: ...
    def list(self) -> list: ...       # 门户页数据（各主机摘要）
```

- 每个 HostMonitor 内部运行 3 个独立 async 任务：Engine（create_engine 按 engine.type 创建）、SshPoller、WsPusher
- 任一任务异常被捕获并记录日志，不影响其他任务与其他主机
- 启动时 Registry 加载全部主机；配置变更需重启（本期不做热加载）

## 4. 采集层设计

### 4.1 LlamaPoller（1s）

端点与频率：

| 端点 | 频率 | 用途 |
|---|---|---|
| GET /health | 1s | 在线检测 |
| GET /slots | 1s | Slot 状态 + 速度差分输入 |
| GET /props | 30s | 模型信息、默认参数、模态 |
| GET /v1/models | 30s | 参数量/嵌入维度/词表/文件体积 |

速度差分算法（每 slot）：

```
state: prev_task_id, prev_decoded, prev_prompt_processed, prev_ts, task_start_ts

on_poll(slot):
  now = time(); dt = now - prev_ts
  if slot.is_processing:
    if prev_task_id is None:
        task_start_ts = now                      # 任务开始事件
    if slot.id_task != prev_task_id or slot.n_decoded < prev_decoded:
        # 新任务（或任务边界）：重置基线，本周期速度 = 0
        prev_task_id = slot.id_task
        prev_decoded = slot.n_decoded
        prev_prompt_processed = slot.n_prompt_tokens_processed
        gen_speed = 0; prompt_speed = 0
    else:
        gen_speed    = (slot.n_decoded - prev_decoded) / dt
        prompt_speed = (slot.n_prompt_tokens_processed - prev_prompt_processed) / dt
        prev_decoded = slot.n_decoded
        prev_prompt_processed = slot.n_prompt_tokens_processed
  else:
    if prev_task_id is not None:
        # 任务结束事件：总 token = 最后 n_decoded，耗时 = now - task_start_ts
        emit(task_end, total_tokens, duration, avg_tps)
        prev_task_id = None
    gen_speed = 0; prompt_speed = 0
  prev_ts = now
```

- 任务开始事件：is_processing false→true → 记录 task_start（任务 ID、prompt token 数）
- 模型变更：/props.model_path 变化 → model_change 事件
- 失败处理：请求超时 3s；连续 3 次失败 → online=false + llama_down 事件；恢复 → llama_up 事件；离线期间保留最后数据

### 4.2 SshPoller（2s）

连接管理：
- paramiko SSHClient，AutoAddPolicy（首次连接自动信任指纹并记录日志）
- transport.set_keepalive(15)
- 断线：指数退避重连 1s→2s→4s→...→30s 封顶；断线时 ssh_down 事件，重连成功 ssh_up 事件
- 静态信息（首次连接采集一次）：hostname、内核、OS 版本（/etc/os-release）、CPU 型号、核数

每周期批量命令（1 次 exec，一次网络往返，全部只读）：

```bash
echo ==GPU==
nvidia-smi --query-gpu=index,name,driver_version,memory.total,memory.used,memory.free,utilization.gpu,utilization.memory,temperature.gpu,power.draw,power.limit,fan.speed,clocks.current.graphics,clocks.current.memory,pcie.link.gen.current,pcie.link.width.current,pstate,temperature.memory,ecc.errors.corrected.volatile.total,ecc.errors.uncorrected.volatile.total,clocks_throttle_reasons.active,cuda_version --format=csv,noheader,nounits
echo ==APPS==
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv,noheader,nounits
echo ==STAT==
cat /proc/stat
echo ==MEM==
grep -E '^(MemTotal|MemFree|MemAvailable|Buffers|^Cached|SwapTotal|SwapFree)' /proc/meminfo
echo ==LOAD==
cat /proc/loadavg
echo ==UPTIME==
cat /proc/uptime
echo ==NET==
cat /proc/net/dev
echo ==DISKIO==
grep -E '^(sd|nvme|vd|dm)' /proc/diskstats
echo ==DF==
df -B1 --output=target,size,used,avail,pcent / /share 2>/dev/null
echo ==PROC==
PID=$(pgrep -x llama-server | head -1)
if [ -n "$PID" ]; then
  echo P:$PID
  awk '{print $14, $15, $23}' /proc/$PID/stat    # utime stime vsize
  grep -E '^(VmRSS|VmSize|Threads)' /proc/$PID/status
  ps -o pcpu=,pmem=,etime= -p $PID
  tr '\0' ' ' < /proc/$PID/cmdline; echo
fi
echo ==PS==
ps -eo pid,comm,pcpu,pmem,rss --no-headers 2>/dev/null
echo ==PSTICKS==
awk 'FNR==1 { n=split(FILENAME, p, "/"); pid=p[n-1]; i=index($0, ") "); if (i > 0) { s=substr($0, i+2); m=split(s, a, " "); if (m >= 13) print pid, a[12], a[13] } }' /proc/[0-9]*/stat 2>/dev/null
echo ==PROCS==
ls /proc | grep -c '^[0-9]'
```

差分计算（后端 DiffEngine，基于连续两次采样）：
- 整机 CPU% = 1 - Δidle/Δtotal（cpu 汇总行）
- 每核 CPU% = 1 - Δidle_i/Δtotal_i（cpu0..cpu5 行）
- 进程实时 CPU% = Δ(utime+stime)/Δt/CLK_TCK（相对单核）
  - 进程卡：/proc/<pid>/stat 第 14/15 字段（时钟滴答，10ms 精度）
  - Top 列表：==PSTICKS== 段（单条 awk 读全部 /proc/<pid>/stat 的 utime/stime，10ms 精度，按 PID 与 ==PS== 段关联）
  - 注意：procps 的 stime 列是启动时间（start time）而非系统 CPU 时间，utime 列不可用（输出 -）；time 列仅 1s 精度，2s 采样窗口下 CPU% 会被量化成 0/50/100/150 台阶值（空闲时全 0 看似"数据是假的"），故必须直接读 /proc
- Top CPU 排序：实时 CPU% → 累计 CPU 时间 → RSS；Top MEM 排序：RSS → 实时 CPU%（各取前 8，后端排序）
- 磁盘读写速率 = Δsectors×512/Δt
- 网络 rx/tx 速率 = Δbytes/Δt
- 首次采样无基线 → 本周期差分指标为 null

### 4.3 EventDetector

状态机（每主机）：

```
llama: online ⇄ offline   （连续 3 次 /health 失败 → offline）
ssh:   connected ⇄ disconnected
task:  idle → running (task_start) → idle (task_end, 带统计)
model: props.model_path 变化 → model_change
prefill: 每任务首条 prompt 行 → prefill_start（含 prompt 总 token 数）
alert:   check_alerts(alerts) 按 metric 跟踪级别变化（normal/warn/danger），变化时发事件（两次事件最小间隔 30s，首次观测只记基线）
```

事件环形：200 条，字段 {ts, level, type, msg}
- task_start/task_end 优先取日志行（launch_slot_ / release）为源，含完整统计（MTP 接受率、上下文占用、耗时）
- boot 事件：日志 "model loaded" 行 → llama_boot（含启动信息）
- prefill_start：LogPoller 在每任务首条 prompt 行发出（按任务 ID 去重，任务结束/重启重置）
- alert：HostMonitor 每次快照 evaluate_alerts 后调用 check_alerts；llama/ssh 不重复（已有专门上下线事件）

### 4.4 LogPoller（日志流）

数据源：`journalctl -u {log.unit}`（systemd journal，只读）

采集方式：
- 专用 SSH channel（与 SshPoller 同一 transport，独立 channel）运行 `journalctl -u llama-server -f -o short-iso --no-pager -n 0` 流式跟随
- channel 断开：重连 + 先 `--since "N seconds ago"`（catchup_sec，默认 30s）补拉，防丢行
- follow=false（兜底模式）：周期（2s）`--since "@<last_ts>"` 拉取新行
- 首次连接拉取最近一次启动块（"listening" 前 200 行）解析 boot 信息

日志行格式（short-iso）：

```
2026-08-28T18:11:25+08:00 ai llama-server[55646]: 50.44.267.087 I slot      release: id  0 | task 14847 | stop processing: n_tokens = 201047, truncated = 0
└─ syslog 时间 ──────────┘ └host┘ └unit[pid]┘  └─ llama.cpp 内部时间 ──┘ └L┘ └subsys┘ └function┘ └─ 消息 ─┘
```

解析规则（正则，按序匹配）：

| # | 模式（简化） | 事件 | 提取字段 |
|---|---|---|---|
| 1 | `slot print_timing: id (\d+) \| task (\d+) \| n_decoded = (\d+), tg = ([\d.]+) t/s, tg_3s = ([\d.]+) t/s` | decode_tick | task_id, n_decoded, tg, tg_3s |
| 2 | `slot print_timing: id (\d+) \| task (\d+) \| prompt processing, n_tokens = (\d+), progress = ([\d.]+), t = ([\d.]+) s / ([\d.]+) tokens per second` | prompt_tick | task_id, n_tokens, progress, elapsed_s, speed_tps |
| 3 | `slot print_timing: ... prompt eval time = ([\d.]+) ms / (\d+) tokens \(([\d.]+) ms per token, ([\d.]+) tokens per second\)` | task_summary.prompt | prompt_ms, prompt_tokens, prompt_speed_tps |
| 4 | `slot print_timing: ... eval time = ([\d.]+) ms / (\d+) tokens \(([\d.]+) ms per token, ([\d.]+) tokens per second\)` | task_summary.eval | eval_ms, decoded_tokens, gen_speed_tps |
| 5 | `slot print_timing: ... total time = ([\d.]+) ms / (\d+) tokens` | task_summary.total | total_ms, total_tokens |
| 6 | `slot print_timing: ... graphs reused = (\d+)` | task_summary.graphs | graphs_reused |
| 7 | `slot print_timing: ... draft acceptance = ([\d.]+) \((\d+) accepted / (\d+) generated\), mean len = ([\d.]+)` | task_summary.mtp | acceptance, accepted, generated, mean_len |
| 8 | `slot release: id (\d+) \| task (\d+) \| stop processing: n_tokens = (\d+), truncated = (\d+)` | task_end | ctx_used, truncated |
| 9 | `slot get_availabl: id (\d+) \| task -1 \| selected slot by (LRU\|LCP similarity)(?:, f_sim_best = ([\d.]+).*)?(?:, f_keep = ([\d.]+))?` | slot_select | method, f_sim_best, f_keep |
| 10 | `slot launch_slot_: id (\d+) \| task (\d+) \| processing task, is_child = (\d+)` | task_start | task_id, is_child |
| 11 | 启动行：`loading model '(.+)'` / `n_slots = (\d+), n_ctx_slot = (\d+), kv_unified = '(\w+)'` / `creating MTP draft context` / `upgrading K from (\S+) to (\S+)` / `verbosity = (\d+)` / `listening on (\S+)` / `W` 级行 | boot_info | model, n_slots, n_ctx_slot, kv_unified, mtp_draft, kv_upgrade, verbosity, listening, warnings[] |

状态机（当前状态，逐行更新）：

```
phase: idle → prompt_processing (prompt_tick) → decoding (decode_tick) → idle (task_end)
current: {phase, task_id, n_decoded, tg, tg_3s, prompt_progress, prompt_speed, prompt_total_tokens, prompt_elapsed_s, is_child, started_at}
started_at: 任务开始时间戳（launch 行写入，task_end 清空；前端算"已运行"时长）
last_prefill: {speed, ts, progress, n_tokens}   # 每条 prompt 行更新，llama 重启清空
context: {used (最近 task_end 的 n_tokens), total (boot n_ctx_slot), pct, remaining, truncated}
mtp:     {acceptance, accepted, generated, mean_len}   # task_end 时更新
kv:      {f_keep, f_sim_best, selection}               # slot_select 时更新
boot:    {...}                                          # boot_info 时更新
```

速度来源优先级：
1. 日志 tg_3s（3 秒窗口，服务端计算）—— 主
2. /slots n_decoded 差分（1s）—— 日志不可用时兜底
- 前端展示标注数据来源（log / API）

失败处理：
- channel 断开 → 重连 + 补拉；期间 log_available=false，速度回退 /slots 差分
- 行解析失败 → 跳过并计数（parse_error 计数器），不影响其他行
- llama-server 重启（PID 变化）→ 重置状态机，重新解析 boot 信息

### 4.5 引擎抽象层（EngineAdapter）

位置：`backend/engine/`（base.py 统一接口 + llama_cpp.py / sglang.py 实现 + `__init__.py` 注册表）。

统一接口（EngineAdapter）：

| 方法/属性 | 说明 |
|---|---|
| `create_engine(cfg)` | 按 engine.type 从注册表创建引擎实例；未知类型抛 ValueError |
| `start() / stop()` | 启动/停止采集任务（async） |
| `online` | 在线状态（连续 FAIL_OFFLINE=3 次失败 → False，恢复 → True） |
| `speeds` | 当前速度（gen/prompt tps）与来源 |
| `build_block()` | 生成快照中该引擎的数据块（llama 与旧 llama 块同形；sglang 见 §5.1 注） |
| `ring_extras()` | 附加 1s 环形序列（sglang：accept_length） |
| `portal_extra()` | 门户卡片附加数据（sglang：queued 等待请求数） |
| `process_flags()` | 进程静态配置（llama 解析 --flags；sglang 来自 /get_server_info） |

注册表：`_REGISTRY = {"llama_cpp": LlamaCppEngine, "sglang": SglangEngine}`；新增引擎（如 vLLM）只需实现接口并注册。

- llama_cpp：包装既有 LlamaPoller / LogPoller，行为零改动
- sglang（SglangEngine，纯只读 HTTP，不调用任何写接口）：
  - 快路径 `/v1/loads`（1s）：多 rank 求和 running / waiting / KV 占用 / 生成吞吐；prefill 累计计数器差分 → prompt 速度、cache_hit、utilization、speculative.accept_length、memory 分区、queues
  - 慢路径（30s）：`/get_server_info` + `/get_model_info` + `/v1/models`（服务配置、模型信息）
  - 鉴权：可选 Bearer API Key（Fernet 加密存储，配置可写 `${SGLANG_API_KEY}` 引用环境变量）
  - 连续 3 次失败 → offline；恢复时发恢复事件（事件类型保持 llama_up / llama_down，engine_name 参数区分引擎）
  - 快照写入 `snap["engine"]`（见 §5.1 注）
  - 进程识别：按 process_cmdline 固定串匹配（默认 "sglang serve"，白名单字符校验，≤128 字符）

## 5. 数据模型

## 13. 本地 CLI（llamalens）

在**被监控主机本地**运行的 htop 风格全屏 TUI，与 Web 面板单主机详情页同源（同一套采集字段、阈值、事件、日志解析规则）。零运行时依赖：单个静态二进制（`CGO_ENABLED=0`），目标主机无需 Go / Python / pip。

### 13.1 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Go 1.24 | 单静态二进制、跨平台、`/proc` 直读方便 |
| TUI 框架 | bubbletea + lipgloss（charm） | 托管终端生命周期（raw 模式 / 备用屏 / 光标 / resize / 退出恢复），**不手写任何 ANSI 转义**——规避早期手写转义导致的全屏乱码 |
| 渲染 | lipgloss 样式 + 自绘 sparkline/条 | 与前端 Terminal 主题同色（cyan/green/amber/red） |

### 13.2 架构（单进程，无网络依赖）

```
llamalens（单进程）
├── collect.LlamaCollector   本机 HTTP：/slots@1s、/props+/v1/models@30s
├── collect.HostCollector    /proc 直读@2s（stat/meminfo/loadavg/net/dev/diskstats/[pid]/stat）+ nvidia-smi@2s + systemctl show
├── logparse.Poller          11 类日志行正则 + 状态机（与 backend/pollers/log_poller.py 同源）
├── collect.JournalCollector journalctl -u <unit> -f 流式（断线 --since 补拉；PID 变化重拉 boot 块）
├── model.World              聚合：差分引擎 + 环形缓冲（llama@1s/3600、host@2s/1800）+ 事件检测 + 告警评估
└── ui.App（bubbletea）      4fps 渲染；q/p/t/g 按键；WindowSizeMsg 自适应
```

数据流与 Web 版一致：采集器 → World.Tick（1s：速度优先级 log tg_3s > /slots 差分、写环、构建快照、评估告警）→ 快照 → 渲染。

任务卡状态以 **/slots API 为准**（任一 slot `is_processing` 即生成中）：journal 流有延迟/丢行，任务开始时日志 phase 滞后于 API，若以日志 phase 为准会出现「Token 速度有值、状态却空闲」。日志 phase 仅用于细化标签（解码中/预填充）；生成中且日志未跟上时显示「生成中」。任务 ID 同理：生成中以 `slot.id_task` 为准（日志 task_id 可能是上一任务残留）。

nvidia-smi 采集细节：`--query-gpu` 含 `uuid`、`--query-compute-apps` 含 `gpu_uuid`，进程**按卡归属**（每张卡「占用」行显示该卡显存，同一 PID 在用到的每张卡各出现一行；旧驱动无 `gpu_uuid` 时回退全部挂第一张卡）。注意 CSV 逗号后带空格（`" 17920"`），数值解析必须 trim，否则 `ParseInt` 失败恒为 0（曾致「GPU 占用 0MB」）。

### 13.3 渲染正确性约束（关键）

早期版本手写 ANSI 转义导致全屏乱码（报文状）。重写后强制三条约束，PTY 实测验证：

1. **不手写转义**：终端生命周期全交 bubbletea；样式全走 lipgloss。
2. **ANSI 感知宽度/截断**：`displayWidth`/`trunc` 按字节跳过转义序列（CSI 引导符 `[` 与终止字节区分），CJK 计 2 列；绝不在转义序列中间截断（否则颜色码泄漏 + 行宽溢出）。
3. **行宽 ≤ 终端宽-1**：写满最后一列会触发终端自动换行，导致后续行整体下移、跨帧重叠。`Render()` 末尾对每行 `trunc(l, w-1)` 兜底；lipgloss `Width/Height` 为内尺寸（不含边框），面板外尺寸需先减 2。
4. **TopBar 截断优先级**：左侧分段为「品牌 · 主机 · 模型  在线状态」，空间不足时先截模型名、再截主机名，保证在线状态始终可见（整段 left 截断会先砍掉末尾的在线状态）。
5. **边框色比前端亮**：前端卡片边框 `#242428` 依赖卡片底色，TUI 无底色时在深色终端几乎不可见，故 TUI 边框用 `#55555e`（其余颜色与前端 Terminal 主题一致）。
6. **各行右缘对齐**：每行总宽必须恰好等于可用宽（终端宽−2）。`lipgloss.JoinHorizontal` 不插入分隔列（易误以为占位——旧代码预留 (n−1) 个 gap 列但实际不存在，导致各行右缘参差）。分栏时末列取余数：`cw=usable/n`、`cwLast=usable−cw×(n−1)`。

### 13.4 配置（flag，默认与 ai.lan 一致）

`--llama-host 127.0.0.1 --llama-port 8080 --process llama-server --unit llama-server --log journal --mounts / --once --dump-frame <file> --no-color`。`--dump-frame` 为排查用：每次渲染帧的原始字节（含 ANSI）写入文件（每次覆盖），复现显示问题时按 `p` 暂停即保留该帧。`--no-color` 为排查用：`lipgloss.SetColorProfile(termenv.Ascii)` 纯文本渲染（lipgloss 渲染时读全局 profile，启动前设置即可全局生效）。进程名 / unit / 端口须与 `hosts.yaml` 对应主机一致（见 README「准备被监控主机」四条件）。`--process` 进程名先 `/proc/<pid>/comm` 精确匹配，失败再回退 cmdline argv[0] basename 匹配（内核把 comm 截断到 15 字符，定制构建可直接传全名，如 `llama-cpp-turboquant`）。TopBar 模型名与 Web TopBar 一致：alias 为完整路径时只显示文件名；模型卡显示完整名 + 体积 + mmproj（mmproj 来自进程命令行 `--mmproj`）。

### 13.5 与 Web 面板的关系

CLI 是**只读旁路**：不经过后端、不写任何文件、不改变 llama-server 状态。采集字段、阈值、事件类型、日志解析正则与后端同源（后端为 Python、CLI 为 Go，规则各自维护但语义一致）。后端升级采集字段时，需同步检查 CLI 是否需要对齐。
